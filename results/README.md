# Quad-Gradient：AES 三批实验结果

## 基本配置

本次实验使用 ASAP7 工艺的 AES benchmark（`aes_p55_h55`），评测 BC、TC、WC 三个 Corner。PyTorch 使用 CPU float64、单线程计算，OpenROAD 使用 8 线程；优化目标仅为 Functional-TC Setup 的归一化 TNS + WNS loss，归一化参考固定为初始工作点。搜索预算为最多 3 批、3 小时，初始 K=100，本次三批均保持 K=100；候选先取全局 Top-K，再按实例去重且不补位，各批串行累积更新。内部采用私有 fresh-route、clean native STA 及常驻 Python worker 刷新梯度图和评分，最终最佳设计通过独立公共评估、形式等价及 runtime 检查；本轮未运行 JPEG 或 GPU 对照。

## 简要分析

1. **Setup 优化有效，但尚未完成时序收敛。** 三角 Setup 均改善，三批全部接受；TNS/WNS 仍为负。停止原因为三批预算耗尽，不能据此认定收敛，也尚未证明梯度排序优于简单排序。
2. **目标仍与综合评分不一致。** 当前只直接优化 TC Setup，未主动修复 Hold 或恢复功耗；TC/WC Hold、WC slew、功耗和面积存在退化，Hold 扣分明显大于 PPA 正贡献，因此不能只用 loss 下降判断竞赛效果。
3. **本次分数提升来自降时，而非新增物理收益。** 与前次相比，三批所选实例/目标、每批 loss 均相同；提交及公共评估后的 DEF/Verilog 逐字节一致，公共 summary 除 runtime 列外全部一致，非 runtime 评分分项也完全相同。每批 apply＋route 共用一个进程，独立 clean STA＋导图保留；初始两个进程加三批各两个，共 8 次 backend，四次建模均读取对应 clean 图，最终发布第三批最佳 checkpoint。OpenROAD backend 仍占 Tool 的 75.15%，不能概括为纯布线时间，也不能据此推导 GPU 收益。完整运行是单次历史对照，且含此前解析复用优化，不代表仅合并 apply＋route 的稳定因果加速比。
